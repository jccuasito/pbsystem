# 13th-month and dashboard loading

## What changed

- Dashboard workspace pages load on demand through dynamic imports. Opening one workspace no longer eagerly imports all 32 workspace pages into the dashboard entry. Existing KeepAlive draft/state retention remains in place.
- Dashboard overview statistics, recent payroll and recent activity are requested only while the overview is selected. Requests share one in-flight load, have a 15-second timeout and no automatic retry, and reuse a successful overview for 30 seconds on quick returns.
- The annual page initially renders 25 employee-agency records and appends 25 more near the bottom while scrolling, like Employee List. This applies to desktop/mobile computation and Release History; there are no Next/Previous controls. A Load more records button also supports keyboard use or browsers without IntersectionObserver. Filter/tab changes reset the visible count, and observers disconnect while inactive/unmounted or while a form is open. Search/status summaries and Excel exports still cover **all matching records**. The GET still returns the complete report; scrolling progressively renders that snapshot without extra API calls or recalculation. This is progressive rendering, not server paging or DOM virtualization.
- One reusable currency formatter replaces constructing a formatter for every amount rendered.
- Annual GETs with the same filters share an in-flight client request; changed filters or deactivation abort the old request, and stale results are rejected even if an aborted transport resolves later. Requests have a 30-second timeout and no automatic retry.
- Automatic refresh/focus/return uses the existing 60-second jittered poll with a 45-second fresh-data window, so rapid focus/visibility events do not keep reloading a fresh report. Manual Refresh and successful mutations request `fresh=1`, bypassing an older in-flight server read that may have started before a write. Background refresh retains the table and cannot replace an open review form's data.
- The server reads each finalized DTR snapshot once per distinct batch, in parameterized chunks of at most 500 IDs, and indexes its employees once. Previously the full batch JSON was transferred/parsed once per employee/payroll/adjustment row. Employee/agency/header/import/release/event lookups now use maps instead of repeatedly scanning entire arrays.
- Simultaneous authorized annual GETs with the same year/agency share raw data computation through `coalesceRead`, except explicit `fresh=1` reads. Permissions remain per caller; settled results/errors and mutation reads are never cached or shared. Approval/payment source checks still run afresh inside their existing transaction. Any supplied `fresh` value other than `1` returns 400.

No formula, rounding, coverage rule, source-hash ordering, eligibility check, payment workflow or response shape was changed. No database migration or live deployment is part of this performance patch.

## Recorded synthetic comparison

Compared the pre-change backend from development commit `d737379` with this patch using the same synthetic 200 employees across 24 cutoffs, including an adjustment, import, saved header, active/voided payment and activity entry. The complete JSON responses were equal, including source hashes.

| Measurement | Before | Optimized |
| --- | ---: | ---: |
| Full batch snapshot rows transferred to the query adapter | 4,801 | 24 |
| Sum of SnapshotJson bytes in those synthetic query results | 227,130,354 | 1,135,415 |
| Backend processing in the recorded local run | 1,065 ms | 155 ms |

These timings are local JavaScript/mock-query measurements, not live MySQL execution, HTTP payload size, full browser load time or a Namecheap guarantee. The optimized implementation adds one batched snapshot SELECT for this fixture (nine SELECTs total) to remove repeated large JSON fields. Actual hosting latency must be measured after an authorized deployment. The comparison artifact is `.data/performance-work/annual-benchmark.json` when the optional baseline run is used; `.data` is not committed.

## Checks

```powershell
$env:THIRTEENTH_TEST_DATABASE='1'
node --test scripts/test-thirteenth-month.cjs scripts/test-thirteenth-month-performance.cjs
```

The SQL integration test shadows persistent tables with connection-local temporary tables and synthetic rows. Do not point it at production.

With Playwright available through `NODE_PATH` and a Chromium path through `CHROME_BIN` / `PORTAL_BROWSER_PATH`:

```powershell
node scripts/test-thirteenth-month-ui.cjs
node --test scripts/test-thirteenth-month-loading-ui.cjs
$env:PORTAL_MOBILE_BROWSER_TEST='1'
node --test --test-name-pattern='dashboard|Admin registration alert' scripts/test-portal-services-ui.cjs
```

The first command uses the synthetic fixture generated by the SQL integration test. It verifies calculations/forms, approvals/payments, Excel, printing and keyboard/mobile behavior. The loading test generates its own 200-record fixture, checks 25-row scroll batches through all 200 rows, Release History, mobile layout, filter reset and full export, rapid-focus/double-click deduplication, abort on navigation and rejection of late responses. Dashboard fixtures cover lazy workspace/notification navigation and overview-only fetching.

For a before/after comparison, save the earlier `server/utils/thirteenthMonthCrud.ts` into an ignored local artifact, set `ANNUAL_PERFORMANCE_BASELINE` to that path, then run `scripts/test-thirteenth-month-performance.cjs`. This optional mode asserts complete response equality and records measurements; normal tests do not depend on an old source file.

The existing account-deletion patch still has its own separate hosting schema prerequisite. Do not skip that migration if deploying the combined changes.
