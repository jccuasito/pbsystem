# Application security controls

Reviewed on November 12, 2026. These are application controls and regression checks, not a penetration-test certification or a promise that every attack is prevented.

## Request boundary

`server/middleware/00-security.ts` runs for the entire application. All APIs default to authenticated staff access; employee-portal APIs use their separate employee sessions. Only the listed signup/login/recovery/verification endpoints and the signup department lookup are public. The existing module middleware still enforces view/edit rights, and resource handlers retain role and ownership checks. The SQL-backup import requires an administrator before its body is buffered.

API paths must use their canonical lowercase, unencoded spelling. Repeated query parameters, control characters, oversized queries, non-object JSON, prototype keys, excessive nesting/row counts, non-finite numbers and invalid scalar identifier types are rejected. Common text/numeric fields cannot be supplied as objects or arrays. API handlers continue to enforce domain-specific amounts, dates, enums, lengths and relationships. DTR and holiday dates also reject impossible calendar dates.

DTR Excel import is a scoped exception to numeric employee identifiers: only POST `/api/attendance/dtr/:id/records` with `ImportRows: true` accepts plain-text `Rows[].EmployeeID` cells such as `EMP-0011` or `DJA-0001`. The importer resolves these to enrolled database IDs. Missing biometric punches remain allowed and can be corrected manually in the DTR. Other IDs and structural/security checks remain unchanged.

Mutation requests check Origin/Referer and Fetch Metadata. JSON APIs reject form and text content types; only the administrator's SQL-import endpoint accepts multipart. Actual streamed body bytes are bounded, including chunked requests without Content-Length. Defaults: 10 MiB JSON, 16 KiB staff/employee auth and employee-portal requests, 3 MiB avatar requests, and 101 MiB administrator SQL-import transport. File handlers impose their smaller decoded-file limits as well. Empty JSON mutations are rejected except logout and manual backup creation.

Values are not stripped of SQL words, apostrophes, angle brackets or Unicode. Those can be legitimate names, notes or references. SQL values use mysql2 `execute(sql, values)` parameters; dynamic identifiers and clauses come from server-owned resource/component maps. Multi-statements and named placeholders are explicitly disabled on the application pool. The authenticated administrator's existing SQL restore operation is intentionally privileged and is not an ordinary parameterized CRUD query.

Headers include private/no-store for APIs, nosniff, same-origin framing, strict-origin referrer policy, restricted camera/microphone/location access, and a limited CSP for frame ancestors, objects and base URLs. This is not a full script-nonce CSP. Vue text interpolation and escaped print templates remain the XSS defense for user text; dashboard `v-html` is reserved for the static icon map.

## Authentication and private data

- Staff passwords have a 12-character minimum, letters/numbers and a 72-byte bcrypt maximum. Email/name/token inputs are type-checked and bounded. Unknown-user login still performs a password-hash comparison.
- Staff JWTs allow HS256 only, check issuer/audience, and require a numeric subject and valid role. Google-signup proof is not a staff session. Both Google routes verify identities through the same implementation; inactive and conflicting linked accounts are rejected.
- New public staff registrations, including first Google logins, are `Viewer` + `Inactive`. Email verification alone does not authorize access. An existing Admin activates the account and assigns department/permissions in Settings; existing accounts are not reclassified. Employee signup retains its matching HR name/government-ID and agreement workflow.
- Staff and employee auth endpoints have bounded, hashed in-memory IP/identity attempt counters. They do not trust arbitrary `X-Forwarded-For` headers. Employee login/recovery also retains its database-backed limits, code-attempt counters, expiry, hashed sessions and revocation. Staff in-memory counters reset on restart and are not shared across multiple workers: use a shared limiter or reverse-proxy/WAF policy for a multi-worker public deployment.
- Government scans and archived payslips remain outside `public`, behind role/ownership-checked routes. Employee sessions cannot select another employee's records merely by changing a query ID. Avatar, employee-photo and logo uploads require canonical PNG/JPEG/WebP base64, decoded size limits and matching file signatures. Signature checks are not antivirus scanning or full image re-encoding.

## Dependencies and deployment

Compatible dependency updates are recorded in `package-lock.json`. SheetJS is pinned to its official 0.20.3 tarball because the public npm `xlsx` version is obsolete. Nodemailer is updated to 10.5.0; glob/minimatch overrides select their patched releases. Nuxt/Vue and related packages were updated within the project's allowed ranges. Test and build after future updates rather than applying `npm audit fix --force` blindly.

The final production audit currently reports **7 low findings, 0 moderate/high/critical**. They originate in unpatched `deepmerge` and its framework/build dependency chains. npm proposes a Nuxt downgrade outside this project's declared range; that downgrade was not applied. The shared JSON boundary rejects prototype keys, but does not constitute a vendor fix for the dependency. Recheck upstream advisories before production use.

For hosting, use a current supported Node LTS release meeting all dependency engines (updated dependencies declare Node 22.22.3+ or 24.15+; the local 24.13 runtime produces engine warnings). Configure the real HTTPS `APP_URL` behind the proxy, a strong private `JWT_SECRET`, a dedicated least-privilege database user, persistent private attachment storage and backups. Do not upload `.env`, SQL backups, `.data` or source maps as public static files. Staff sessions use secure cookies in production. Employee-photo and avatar URLs retain their existing `/uploads/...` spelling but are now authenticated server routes, backed by `.data/profile-images` (or `PROFILE_IMAGE_STORAGE_DIR`). Before deployment run `node --env-file=.env scripts/migrate-private-profile-images.mjs` on the machine holding the original files, then transfer the private folder separately along with the other private attachments. The repeat-safe migration verifies SHA-256 before removing each public copy and changes no database URLs. Build a fresh output afterwards; remove stale public upload copies from old deployments/CDNs. An upstream web server must proxy these legacy upload URLs to Node, not publish private storage or serve old image copies. These files are ignored by Git and must be included in secure file backups. Existing Git history may still contain previously committed images; no history rewrite was performed.

## Verification

### User-facing request failures

Frontend request catches use `shared/utils/requestError.ts`. Connection failures, timeouts and 5xx responses display a fixed public message rather than ofetch's raw `message` (which includes the request URL and query). Expected application validation/conflict messages are retained when they contain no technical diagnostics. The formatter rejects API paths, stack/file paths, HTML and common SQL/driver diagnostics, including when supplied as a nominal 4xx message. Local form and Excel validation messages remain available. Formatting does not mutate the original error or the workflow codes used for duplicate detection and conflict handling, and introduces no automatic mutation retry.

This is a presentation boundary, not SQL injection protection or API response redaction. Authentication, authorization, input validation and parameterized queries remain the security controls. Browser developer tools can still show network requests; API paths are not secrets. Local Nuxt development diagnostics are for development, and public hosting must run a production build. Quitting the Nuxt process makes the service unavailable until it is started again.

`node scripts/test-request-errors.cjs` checks transport, internal-error and validation cases. With Playwright available, `ERROR_BROWSER_TEST=1 node scripts/test-request-errors-ui.cjs` exercises the real DTR and portal components with ofetch against synthetic 503, network and validation responses, then verifies recovery. It does not stop the user's server or submit writes.

Verification completed November 12, 2026: 251 unit checks passed (30 optional integration/browser checks skipped in that run); a separate database-isolation run passed all 15 checks; the billing, 13th-month and mobile employee-portal browser checks passed; and the production build completed. Fourteen read-only local production checks passed, including authenticated DTR retrieval, rejection of impossible dates/repeated query keys/malformed JSON/cross-origin mutations, and private image access (guest denied, authenticated bytes matching storage). The 12 existing employee photos/avatars were migrated with verified copies; the second migration run changed no files. These checks do not replace testing every production workflow or an independent security assessment.

- `node scripts/audit-security.cjs`: API/SQL/import inventory saved to `.data/security-source-audit.json`; detects missing relative imports, runtime `.query` calls and direct request interpolation. This is a regression aid, not complete taint analysis. Dynamic SQL builders were also reviewed for fixed resource maps, placeholder lists and clauses with bind values.
- `node --test scripts/test-security.cjs`: real local HTTP tests for global API gates, JSON/body limits, CSRF, repeated parameters, auth throttling, malformed session claims and staff activation, plus a DTR injection-payload bind-value regression. No real login credentials or outbound emails are used.
- Existing unit/browser suites verify payroll, DTR, billing, employee forms, imports/exports and printing after dependency updates. The standalone `test-payroll-adjustments.cjs` and `test-payroll-verified-missed-day.cjs` require prepared live fixtures and must not be indiscriminately included in the unit-test glob.
- Portal/government-ID/archive integration suites use synthetic connection-local temporary tables and isolated temporary files. They cover employee ownership, private attachments, recovery and HR correction requests without changing actual payroll amounts.
